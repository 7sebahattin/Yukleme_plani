# Çek-Senet (ceksenet_*)

> v528. Kapı v550'den beri `muhasebe_modul_can` (Roller `muhasebe.cek_senet.*`; bkz. `rol-yonetimi`) (sidebar "Çek-Senet" grubu, `nav_muhasebe_gruplari()`; 3 sayfa). kasa-modulu / stok-modulu kalıbının eşi. Önkoşul şemalar: Cari + Kasa (`kasa-modulu` ve `cari-modulu` skill'leri). Çek-senet cari ve kasaya YALNIZ onların çekirdek fonksiyonlarıyla bağlanır; tersi YOK (kasa çek-senedi bilmez).

## Kapsam
- **Sayfalar (kök, hepsi GET-only):** `cek_dekontu` (sinif=cek) ve `senet_dekontu` (sinif=senet) — ortak `ceksenet_sayfa_govde($pdo,$sinif)`; GET: `?yon=alinan|verilen` · `?id=N` evrak detayı (panel açık) · `?yeni=1&yon=` bordro formu · süzgeç `?ara= &durum=acik|tumu|<tek durum> (varsayılan acik) &donem=tumu|gecmis|7g|30g|bu_ay|ozel (&bas &bit; VADE üzerinden) &cari= &sayfa=` · `?parca=detay&id=N` · `?parca=cari_ozet&cari=N` kısmi yanıt (`ceksenet_parca()`, render_header'dan ÖNCE). `cek_tanimlari`: `?sekme=banka|karne`.
- **Yazma TEK uç `cek_kaydet.php`** (yalnız POST; ikisi için). Sıra: yöntem → `require_login` → `ceksenet_no_store` → JSON başlığı → `csrf_check` → `db()` → `ceksenet_sayfa_kapisi` (çek-senet + cari + kasa) → dalın İLK ifadesi tek `ceksenet_kapi(...)` → yalnız `ceksenet_core` fonksiyonu → `ceksenet_cevap`. 6 dal:

| `islem` | yetki | çekirdek / alanlar |
|---|---|---|
| bordro_kaydet | write | `ceksenet_bordro_kaydet`: `sinif, yon, cari_id, tarih, aciklama?, istek_anahtari?` + paralel diziler |
| islem_uygula | write | `ceksenet_islem_uygula`: `ids[]` (ya da `id`), **`gecis`** (geçiş adı), `tarih, cari_id?, kasa_id?, aciklama?, istek_anahtari?, eksiye_izin?` |
| hareket_iptal | delete | `ceksenet_hareket_iptal`: `id` = **HAREKET id'si** (kayıt id'si DEĞİL), `neden` |

  `islem` bu uçta YÖNLENDİRME anahtarıdır; durum geçişinin adı ayrı `gecis` alanıyla gelir (`islem=islem_uygula&gecis=ciro&ids[]=…`; çekirdek `$g['gecis'] ?? $g['islem']` okur). JSON 200 / 422 / 409 / 403 / 503 / 500. 409 kodları: `yetersiz_bakiye` · `mukerrer` · `gecersiz_gecis` (+ `kayitlar[]`) · `son_degil` · `kullanimda`. Yanıt anahtarları: `ok,id,kayit_id,idler,bordro_no,belge_no,hata,alanlar,satir_hatalari,kayitlar,uyari,yonlendir,tekrar,kod,bakiye,eksik,toplamlar,ortalama_vade,yeni_durum,sinif,yon`. Klasik form 303 `geri` YALNIZ `^(cek_dekontu|senet_dekontu|cek_tanimlari)\.php(\?…)?$`, aksi `cek_dekontu.php`.
- **Çıktı ucu `cek_cikti.php`** (salt okunur GET): `?bordro=BRD-YYYY-NNNNNN[&otomatik=1]` A4 bordro (evrak listesi + toplam + ortalama vade) · `?sinif=cek|senet&bicim=xlsx|csv` + liste süzgeçleri (`require_perm('reports.export')` + `export_audit('ceksenet','liste',…)`; CSV `;` + BOM; XLSX'te pb başına özet sayfası, pb'ler toplanmaz).
- Çekirdek `config/ceksenet_core.php` (`require_once cari_core.php` + `kasa_core.php`), işaretleme `config/ceksenet_ui.php` (SORGU yok), istemci `assets/ceksenet.js` + `ceksenet.css` (kök `.ceksenet#ceksenet`, önek `cs-`; style.css/app.js'e DOKUNMAZ, SW SHELL'e girmez).
- **Tablolar** (`ceksenet_tablolar()`): `ceksenet_kayitlar` (evrakın kendisi; sinif cek|senet × yon alinan|verilen; `portfoy_no` ÇA-/ÇV-/SA-/SV-YYYY-000123) · `ceksenet_hareketler` (INSERT-only geçmiş; `belge_no` CSH-YYYY-000123, `bordro_no` BRD-YYYY-000123 = bordronun/işlemin İLK hareket id'si tabanlı; `istek_anahtari` UNIQUE) · `ceksenet_tanimlar` (tur banka|karne; tohum 10 banka yalnız tablo yeni kurulduysa).

## Değiştirmeden önce oku
- **Durum makinesi TEK kaynak `ceksenet_islemler()`** (motor tablo güdümlüdür; UI modal alanlarını da `#csVeri.islemler` ile BU yapıdan üretir: `etiket(+etiket_senet)`, `yon`, `onceki[]`, `yeni`, `dekont`, `cari[]`, `cari_zorunlu`, `kasa_sec`, `para`, `yer`, `etki`, `toplu`). Yeni geçiş = bu diziye satır; motoru/UI'yı ayrıca kodlama. 12 işlem:

| gecis | yön | önceki → yeni | cari etkisi | kasa etkisi |
|---|---|---|---|---|
| giris | alinan | — → portfoy | kayıt carisine Alacak | — |
| ciro | alinan | portfoy → ciro | hedef cari (zorunlu, aktif) Borç; `yer_cari_id` | — |
| tahsile_ver | alinan | portfoy → tahsilde | — | banka-tipi kasa zorunlu (`yer_kasa_id`); para hareketi yok |
| teminata_ver | alinan | portfoy → teminatta | — | banka-tipi kasa isteğe bağlı; para hareketi yok |
| portfoye_al | alinan | tahsilde, teminatta → portfoy | — | yer temizlenir |
| tahsil_kasa | alinan | portfoy → tahsil | — | seçilen kasa/banka `kaynak_giris` |
| tahsil_banka | alinan | tahsilde → tahsil | — | `yer_kasa_id` kasasına `kaynak_giris` |
| karsiliksiz (senette "Protesto") | alinan | portfoy, tahsilde, ciro → karsiliksiz | kayıt carisine Borç; önceki durum ciro ise `yer_cari`'ye Alacak (`cari_hareket2_id`, "ciro geri alma") | — |
| iade | alinan | portfoy, karsiliksiz → iade | yalnız önceki portfoy ise kayıt carisine Borç | — |
| cikis | verilen | — → verildi | kayıt carisine Borç | — |
| odendi | verilen | verildi → odendi | — | kasa zorunlu (çekte karnenin banka hesabı varsayılan) `kaynak_cikis` |
| iade_alindi | verilen | verildi → iade | kayıt carisine Alacak | — |

  Ek durum `iptal` (giris/cikis iptali). Açık (vadesi izlenen) durumlar: portfoy, tahsilde, teminatta, verildi (`ceksenet_acik_durumlar()`). Kasa seçilen kasanın pb'si evrakın pb'siyle AYNI olmalı (aksi hata, `alanlar[kasa_id]`); pasif/görünmeyen kasa seçilemez. Cari dekontları `cari_hareket_ekle` tur `alacak_dekont`/`borc_dekont`, açıklama otomatik (`"Çek girişi ÇA-… · Vade dd.mm.yyyy · BANKA seri"`), kaynak `['modul'=>'ceksenet','id'=>HAREKET_id]`; kasa `kasa_hareket_ekle(…, ['modul'=>'ceksenet','id'=>hareket_id])` tur `kaynak_giris|kaynak_cikis`. Bir hareket EN ÇOK 2 cari dekontu yazar (ikisi aynı kaynak id'yi taşır; `cari_kaynakli_iptal` ikisini birden iptal eder).
- **İptal kuralı:** `ceksenet_hareket_iptal($pdo,$HAREKET_id,$neden,$uid)` YALNIZ kaydın SON geçerli hareketini iptal eder (aksi 409 `son_degil`, "önce <belge> iptal edin"); durum + `yer_cari_id`/`yer_kasa_id` hareketteki `onceki_*` değerlerine döner; `giris`/`cikis` iptali = kayıt durumu `iptal` (listede üstü çizili, toplamlara girmez). Kaynaklı cari ve kasa satırları HER ZAMAN iptal çağrısına girer (`cari_kaynakli_iptal` + `kasa_kaynakli_iptal`, ikisi idempotent) — hareket satırındaki `*_hareket_id` boş kalmış olsa bile. Kayıt, hareketin bıraktığı durumda değilse (yarış) HEPSİ geri (`son_degil`). Detayda `hareketler[].son` bayrağı iptal düğmesini açar. Cari/kasa ekranlarından bu kaynaklı satırların iptali 409 `kaynakli`.
- **Bordro** (`ceksenet_bordro_kaydet`): başlık + PARALEL DİZİ satırlar `seri_no[] banka_ad[] sube[] hesap_no[] borclu[] kefil[] yer_adi[] duzenleme_tarihi[] vade[] tutar[] para_birimi[] karne_id[]` (ya da `satir[]`); tümüyle boş satır atılır; `CEKSENET_SATIR_MAX = 30` (max_input_vars ≈ 30×12), toplu geçiş `CEKSENET_TOPLU_MAX = 100`; hata `satir_hatalari[i]` (i = DOM sırası). Her satır = kayıt + hareket + cari dekontu, ortak `bordro_no`; alınan → `giris`/Alacak, verilen → `cikis`/Borç. Senette banka/şube/hesap boş, çekte kefil boş. Düzenleme tarihi vadeden sonra olamaz. Verilen çekte `karne_id` → banka/şube/hesap karnenin banka hesabından gelir, pb karne hesabıyla aynı olmalı; numara karne aralığı dışındaysa yalnız `uyari`. **tx içinde YAZMADAN SONRA `return hata` YASAK** — `cari_tx` o dönüşü COMMIT eder, yarım bordro kalır; hata → `throw new RuntimeException(…, CEKSENET_IC_HATA)` (catch kodu ayırır; `$ic`/`$mk` ham sonucu taşır). Yazmadan önce doğrulama dönüşleri serbest. Commit SONRASI hesaplar (toplam, ortalama vade) try/catch içinde — istisna kaydı 500'e çevirmez, audit her koşulda yazılır.
- **Mükerrer kuralı TEK yardımcı `ceksenet_mukerrer_mu($sinif, $a, $b)`** (v528; alınan + verilen çek; bordro içi [`$gorulen` listesi] ve DB karşılaştırması [`ceksenet_mukerrer_bul`] aynısını çağırır; senette kontrol YOK): iki çek mükerrer ⇔ banka (`cari_fold`) eşit VE seri (`cari_fold`) eşit VE (hesaplardan biri boş YA DA hesaplar eşit [`ceksenet_hesap_norm`: boşluk/tire atılır, fold]). Karneli verilen çekte "hesap" = karnenin banka KASASI (`ceksenet_karne_kasa_id`): iki karneli çek yalnız AYNI kasaysa aynı hesaptır (aynı bankada iki FARKLI banka-kasalı karnede aynı seri KABUL; IBAN boş olsa da); karneli ↔ karnesiz: karnesizin hesabı boşsa mükerrer, doluysa kasanın IBAN'ı ile kıyaslanır (IBAN boşsa mükerrer). Karnesiz verilen çekte iki dolu FARKLI hesap_no artık meşru. Eski `ceksenet_mukerrer_anahtar` KALDIRILDI (anahtar karşılaştırması geçişli olmayan bu kuralı ifade edemez). `ceksenet_mukerrer_bul` `iade`/`iptal` durumundakileri saymaz. 409 `mukerrer` + `satir_hatalari`. Kilitsiz okur: yarışı bordro tx'inin cari kilidi daraltır, tam kapatmaz.
- **Ortalama vade:** `ceksenet_ortalama_vade(array $satirlar, string $baz)` SAF; gün = round(Σ(kuruş×gün)/Σkuruş) (gün = vade − baz tarih; yarım sıfırdan uzağa; tam sayı aritmetiği, taşmada bcmath), tarih = baz + gün; PARA BİRİMİ başına ayrı. **Sunucu esas** (bordro yanıtı `ortalama_vade`, `cek_cikti` bordrosu); `ceksenet.js` seçim çubuğundaki ve form altındaki değer yalnız ÖNİZLEME (aynı algoritma). Seçimin toplamı/ortalaması `ceksenet_secim_ozeti`. Formülü değiştirirsen çekirdek + JS birlikte (ui smoke sunucu = önizleme eşitliğini denetler).
- **Tutar / özet / bordro çıktısı (v528):** bordro satırı tutarı `kasa_tutar_coz` ile okunur (belirsiz "1,500" → `satir_hatalari[i][tutar]`, bkz. kasa skill'i); bordro formunda her tutarın altında `[data-tutar-onizleme]`. Liste özeti `durum=iptal` süzgecinde iptal edilenlerin toplamıdır (`ozet_iptal`; not "bu toplam yalnız iptal edilen kayıtlara aittir"). `cek_kaydet` hareket iptali `yonlendir` = `?yon=<kaydın yönü>&id=<kayıt>`. Bordro çıktısı başlığı `ceksenet_bordro_baslik`: giriş/çıkış "ÇEK GİRİŞ/ÇIKIŞ BORDROSU", işlem bordroları işlem etiketiyle ("ÇEK CİRO ET BORDROSU"); cari satırı `ceksenet_bordro_cari_etiket` ("Ciro edilen cari") ve carisiz işlemde BASILMAZ. İşlem/bordro sonrası toast'ta ve detay zaman çizgisinde bordro no `cek_cikti.php?bordro=` bağlantısıdır (yeni sekme; toast bağlantısı `pointer-events: auto`, toast'un kendisi `none`). CSV metin hücreleri `kasa_csv_metin` ile `'` önekli.
- **Geçiş (`ceksenet_islem_uygula`):** toplu ids sıralı; HEPSİ aynı sinif/yön ve işlem için izinli olmalı, biri uymazsa HİÇBİRİ yazılmaz → 409 `gecersiz_gecis` + `kayitlar[]` (id, portfoy_no, durum, neden). Sıra: kayıtlar kilitli oku → istek anahtarı yeniden dene → izin kontrolü → kasa çözümü (`ceksenet_kasa_coz`) → yazma. Kayıt güncellemesi `… WHERE id = ? AND durum = ?` ve `rowCount() === 1` zorunlu (aksi iç hata, hepsi geri). `odendi`'de kasa bakiyesi yetersizse 409 `yetersiz_bakiye` (+ `bakiye`, `eksik`); UI "Yine de kaydet" AYNI `istek_anahtari` + `eksiye_izin=1`. `ceksenet_izinli_islemler($kayit)` yön + önceki durumdan türetir (iptal kaydında boş).
- **Defter değişmezliği ve UPDATE beyaz listeleri** (gate smoke tam metin): `ceksenet_kayitlar` DELETE YOK; UPDATE yalnız `portfoy_no = ?, bordro_no = ?` ve `durum = ?, yer_cari_id = ?, yer_kasa_id = ?, updated_at = ?, updated_by = ?`. `ceksenet_hareketler` DELETE YOK; UPDATE yalnız `belge_no = ?, bordro_no = ?, cari_hareket_id = ?, cari_hareket2_id = ?, kasa_hareket_id = ?` ve `durum = 'iptal', iptal_at = ?, iptal_by = ?, iptal_neden = ?` (`AND durum = 'gecerli'`). Düzeltme = iptal (neden 3–500) + yeniden gir. Taslak YOK. `ceksenet_tanimlar` güncellenir; kullanılan tanım silinmez (409 `kullanimda`, pasifleştir).
- **Kilit sırası:** kayıt satırları (`ceksenet_kayitlari_kilitle_oku`, id artan, MySQL `FOR UPDATE`; tx'in İLK ifadesi) → kasa (`kasa_kart_kilitle` kasa çekirdeği içinde) . **İstisna:** bordro tx'i kayıt satırı henüz olmadığından başında cari satırını kilitler (`SELECT id FROM cari_kartlar WHERE id = ? FOR UPDATE`; çekirdekteki TEK doğrudan cari SQL'i, gate smoke bu dizgeyi birebir sabitler) ve kilit sonrası istek anahtarını yeniden dener. Kilitler yalnız MySQL'de çalışır; testler SQLite → bu kısım yalnız statik doğrulandı.
- **Karne = banka tipi kasa:** `ceksenet_tanimlar` tur=karne → `kasa_id` (tip=banka kasa kartı; aktif, aktif depoda görünür), `ilk_no` (yalnız rakam, ≤20 hane), `yaprak` (1–1000). `ceksenet_karne_siradaki` yalnız ÖNERİ (kullanılan en büyük sayısal no + 1; kayıtta doğrulanmaz).
